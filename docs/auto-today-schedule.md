# 需求文档：启动时自动生成当日排期

- 状态：已定稿（2026-11-21）
- 关联模块：`src-tauri/src/commands/planner.rs`、`src/hooks/useAutoSchedule.ts`、`src/pages/Settings.tsx`

## 1. 背景与问题

任务（`tasks`）和排期（`task_sessions`）是两套数据：任务说明「学什么、多少课、第几轮」，排期说明「哪天哪个时段学」。
今日计划页只渲染 `date = 今天` 的排期，因此**有主线任务 ≠ 今天有安排**。

实测场景（2026-11-21）：库存里有两个主线任务（数学必修一 18 课、物理必修一 14 课，均未归档），
但 `task_sessions` 只有 3 条，全落在 2026-11-18，于是今日页与首页卡片都是空的。
用户需要手动进任务详情点「一键排一周」，才知道今天该学什么。

## 2. 目标

打开应用时，如果今天完全空着，就按学生自己设定的每日可用时段，把主线任务自动排进今天。
学生不需要先想「今天学什么」，打开就能开始。

## 3. 规则

### 3.1 触发

- 触发时机：主窗口启动后调用一次 Tauri 命令 `ensure_today_schedule`。
- 只在 Tauri 桌面环境执行（浏览器预览不执行）。
- 失败静默：命令报错只写控制台，不弹窗、不阻断启动。

### 3.2 作用范围

- 只处理**今天**（本地日期），不预排未来几天。未来几天仍然由「一键排一周」负责。
- 只排**主线任务**（`type = 'main'`）。副本任务没有总量语义，不参与自动排期。

### 3.3 幂等（关键约束）

- 今天只要已经存在任何**真实场次**（状态为 `planned` / `done` / `missed`），就**一格都不排**。
  用户自己安排过的日子，应用不插手。
- 状态为 `rescheduled` 的旧记录不算「有安排」：那一场已经挪到别的日子了，今天确实还空着。
- 结论：同一天反复启动应用，排期行数不增长。

### 3.4 排期规则

| 项 | 规则 |
|---|---|
| 时段来源 | 设置页「每日可用时段」（`app_settings.daily_slots`）；没设置时用默认三段 08:00–09:00 / 14:00–15:00 / 19:00–20:00 |
| 每日上限 | `app_settings.daily_limit_minutes`，默认 480 分钟（与「一键排一周」同一套解析） |
| 时段被占 | 整天不排（见 3.3：今天已有真实场次就一格都不加） |
| 任务筛选 | `type='main'` 且 `archived = 0` 且 `deleted_at IS NULL` |
| 本轮已满 | 本轮 `sum(actual_units)` ≥ `total_units`（`total_units > 0`）的主线不排——要先推进轮次 |
| 多任务分配 | **轮转**：时段按顺序走，任务按 id 顺序轮流占用，保证每科都有场次 |
| 每场计划量 | `planned_units = 1`（与「一键排一周」一致） |
| 轮次 | 取任务当前 `current_round` |

### 3.5 开关

- `app_settings.auto_schedule_today`：写 `"0"` / `"false"` 表示关闭，其余（含缺省）表示开启。**默认开启**。
- 设置页提供「启动时自动排今天的计划」勾选框，关闭后启动不再自动排。
- 开关在**后端**判定：前端拿不到开关也不影响后端行为。

## 4. 不做的事

- 不预排明天及以后（避免和「一键排一周」重复产出、也不越权替用户决定未来几天）。
- 不排副本任务。
- 不修改已存在的排期、不改期、不删除。
- 不动 XP / 连击 / 成就（自动排出来的只是 `planned` 场次，完成后才进入统计）。

## 5. 接口

### `ensure_today_schedule`（Tauri command）

入参：无（日期取本地当天；Rust 侧实现保留 `date: Option<String>` 供测试注入）。

返回：

```jsonc
{
  "date": "2026-11-21",       // 本次处理的日期
  "created": 3,               // 新建的排期数
  "skipped": 0,               // 因超上限 / 时段被占而跳过的格子数
  "taskIds": [4, 5]           // 参与排期的任务 id（去重，按出现顺序）
}
```

`created > 0` 时前端失效 `sessions` / `sessions-range` / `sessions-task` 三组缓存，并广播给桌面悬浮窗。

## 6. 测试要点

Rust（`src-tauri/tests/auto_schedule_test.rs`）：

- 今天空着 + 有主线 → 按默认三段建场次，日期是今天。
- 第二个主线也参与：两个主线轮流占时段，每科都有场次。
- 幂等：连跑两次，第二次 `created = 0`，总行数不变。
- 今天已有 `planned` 场次 → `created = 0`，不新增。
- 今天只有 `rescheduled` 旧记录 → 仍然自动排（今天确实空着）。
- 开关写 `"0"` → `created = 0`。
- 归档任务、回收站任务不参与排期。
- 本轮已做满的主线不排期。
- 每日上限生效：上限 60 分钟时只排下第一段。

前端（`src/hooks/__tests__/auto_schedule.test.tsx`、`src/pages/Settings/__tests__/settings_auto_schedule.test.tsx`）：

- 启动时调用后端命令；`created > 0` 时失效排期缓存。
- `created = 0` 时不失效缓存。
- 非 Tauri 环境不调用。
- 后端报错不抛到渲染层。
- 设置页开关：未设置时为开，关掉写 `auto_schedule_today=0`；存 `0` 时为关，打开写 `1`。
